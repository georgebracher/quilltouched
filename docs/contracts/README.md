JSON Schema (draft 2020-12) contracts at the three seams between the LLM layer and the engine. These are data contracts only — no prompts live here. Drafted with Team A's roadmap material; fields marked PROVISIONAL need Team A sign-off before Sprint 1 parser work.

| File | Seam | Producer → Consumer |
|---|---|---|
| `intent.schema.json` | Player utterance → engine | Intent parser (haiku, structured output) → rules engine |
| `outcome.schema.json` | Engine → narration | Rules engine → narrator prompt builder |
| `narration_context.schema.json` | State → narration | Context assembler → narrator prompt builder |

## Envelope discipline (applies to all three)

- **`additionalProperties: false` at every level.** Unknown keys are schema violations, not passengers.
- **All current core fields are required.** Absence is expressed as `null` or `[]`, never by omitting the key. Additive public contract fields may stay optional only to preserve historical narration fixtures/records; current producers should still emit them.
- **Entity IDs** are lowercase snake_case (`^[a-z][a-z0-9_]*$`). Prefix conventions (`npc_`, `crt_`, `itm_`, `obj_`, `loc_`, `hyp_`) are convention, not schema-enforced — Team A owns the final ID scheme.

## intent.schema.json — ParsedIntent

A parse of what the player **declared**, never a ruling. North Star pillar 1: no LLM call ever decides success, difficulty, or state.

- **Every `*_hint` field is advisory.** `plausibility_hint` is the parser's common-sense read only; the engine tiers the action from true sheets and authored laws. The parser must not pre-deny legal fiction: "I fight the dragon" is `plausible` (the engine will tier it hopeless), a sealed feat like resurrection is `dubious` (the engine checks components), only genuine physics violations ("I declare myself god") get `impossible_in_fiction`.
- **`dialogue` carries the speech/action split.** Verbatim quoted speech must land in `quoted_speech`, never be paraphrased into `approach`. Paraphrased speech ("Ask the librarian about dragon anatomy") keeps the object with `quoted_speech: null` — the narrator voices the line.
- **`duration_hint` carries the player's words**, not hours. `until_condition` binds to a world clock ("until the caravan leaves"); `explicit` for stated spans. The engine prices real duration and previews it at the commit beat (playbook §7 rule 3 — never reinterpret an innocent verb into an unseen obligation).
- **`ambiguity_flags` records the parser's doubts.** They are carried with the intent and shown in the workings panel; nothing the engine decides reads them, and they do not force the commit beat (George, 25 Oct 2026). Open vocabulary; starter registry: `could_be_feint_or_fight`, `compound_action`, `ambiguous_target`, `ambiguous_addressee`, `idiom_or_literal`, `sarcasm_or_literal` (utterance reads as sarcasm/rhetoric but is typed as a declaration), `contradictory_negation` (utterance negates and asserts the same action — "I definitely don't stab him (I stab him)"; parse the operative intent and flag it).
- **`stat_hint` vocabulary is LOCKED** (`might/finesse/wits/will/presence/lore`) — sprint-1 interface decision 1; matches `docs/engine/stats.md`. Keep in lockstep with `everquill_engine`.
- **Compound actions (v0 ruling):** one primary `action_type` + `compound_action` flag + all targets listed. Whether the parser should instead emit multiple sub-intents is an open Sprint 1 decision with Team A; the schema deliberately does not model sub-intents yet.

## outcome.schema.json — ResolvedOutcome

What the engine emits for narration, **after** the outcome is committed to the append-only event log (`event_id`). Narration binds to the record, never the reverse.

- **Ladder encoding** (roadmap §3.1): `tier_resolved` is the full seven-tier ladder; `risk_label_shown` is the pre-roll label in words (Guarded→Suicidal), never percentages; `outcome_tier` is the 2d6 three-tier result. Conditional rules encoded in the schema: trivial/impossible ⇒ no dice, no outcome tier, no risk label; routine/risky/desperate/hopeless ⇒ dice + label + tier all present; **hopeless ⇒ `outcome_tier` is always `miss`** (the roll picks *how* you fail — best case is never victory). Sealed is left flexible: components met ⇒ real roll; unmet ⇒ fails forward as `miss` with `dice: null`.
- **`dice` is post-roll Chronicle data** (playbook §3): honest 2d6, modifier breakdown, total — every death auditable without trusting prose. **Modifier labels must be KNOWN-safe**: named from the player's known-sheet vocabulary, never leaking true-sheet values. `total` arithmetic can't be schema-enforced; the eval harness re-checks it.
- **`state_deltas` is a discriminated union** (`delta_type`) of 11 typed deltas: `hp`, `coin`, `inventory`, `flag`, `position`, `intel` (a claim write with provenance), `deed`, `title`, `clock`, `timer_started`, `death_record`. The `death_record` delta is the sealed death record (heir flow phase 1) — committed before narration, and the thing `bind_to_death_record` binds to. Every miss should write something (the loop always deposits value); empty arrays are legal only for pure narrate-only beats. Derived events (re-tier toasts, title-threshold recognition) are projections, not deltas.
- **`movement_blocked` + `system_note` are deterministic routing fields.** A blocked movement is not a failed travel scene; it is a no-position-delta no-op with an engine-written exit list. The API must use `movement_blocked`, not string matching, to skip narration and surface `system_note`.
- **`narration_constraints` is a closed enum** — extending it is a contract change, not a prompt tweak:

| Constraint | Source |
|---|---|
| `no_npc_awe_unearned` | Realist Hero failure; standing prompt-QA rule (roadmap §7, playbook conflict 6) |
| `bind_to_death_record` | Death narration binds to the sealed record (playbook §6 phase 1) |
| `entity_facts_only` | Narrate only committed entities/facts; no improvised dukes (roadmap §3.5) |
| `no_chronicle_contradiction` | The Chronicle is authoritative (roadmap §3.3) |
| `no_invented_witnesses` | Deed/death records carry the real witness list |
| `no_invented_final_words` | Most deaths abrupt; no auto-eloquence (roadmap §3.7) |
| `no_success_framing` | For miss/hopeless/fails-forward: prose must not imply achievement |
| `impossible_tier_irony_licensed` | Irony licensed ONLY inside the impossible tier (playbook conflict 7) |
| `no_furniture_commits` | Scenes where the narrator may not mint furniture entities (death beats, sealed rites) |

## narration_context.schema.json — NarrationContext

The context assembler's output envelope — the **only** state that may reach the narrator, alongside a ResolvedOutcome.

- **Leak audit anchor: true-sheet fields are structurally absent from this schema by design.** There is no field where a real stat, hidden motive, or engine difficulty can legally travel; combined with `additionalProperties: false` everywhere, a leak is a schema violation, not a style problem. The CI leak audit (roadmap §7) validates every narrator payload against this file.
- **The Chronicle/Inquiry split is structural:** `known_sheet_slices` carries Chronicle-layer facts (exact, authoritative, narrator cannot contradict); `salient_claims` carries Inquiry-layer claims with the full provenance stamp (fallible — what the character *believes*, with `confidence` = evidence consistency, never truth-probability).
- **`scene_manifest` is the perceived scene** — the same fog-of-warred subset the client tableau renders. `state_tags` on entities are externally visible conditions only.
- **`token_budget`** makes the assembler's budget (~2–3k) and summarize-vs-quote policy explicit in the envelope, so cost guards can assert on it.
- **Claim shape duplication:** `outcome.schema.json#/$defs/claim_write` (write-time, no `claim_id`/links) and `narration_context.schema.json#/$defs/claim` (read-time, with `claim_id` + corroboration/contradiction links) are deliberately kept as in-file copies to avoid cross-file `$ref` resolver requirements at Sprint 0. **They must stay in lockstep**; Team A may hoist a shared `common.schema.json` when the engine schemas land.

## Validation

Schemas self-validate against the 2020-12 metaschema, and every golden utterance in `evals/golden-utterances.jsonl` validates against `intent.schema.json` (see `evals/README.md`). Re-run after any contract change — golden-set gating on every prompt/contract change is the Sprint 1 risk mitigation for parser quality.

# Everquill PostgreSQL event-store proposal

## Recommendation

Use one Railway PostgreSQL database with three logical schemas:

- `canon`: immutable events plus append-coordination metadata.
- `read_model`: disposable, rebuildable gameplay projections.
- `ops`: disposable worker/timer state.

The event log remains the sole source of truth. Character state, knowledge, claims, scene manifests, rumors, and timers are projections of events.

Use a transactionally updated counter for `global_position`, not `bigserial`/identity. PostgreSQL sequences are not rolled back; more importantly, concurrent transactions can obtain positions and commit out of order. A projector that checkpoints the highest visible identity can then miss a lower, late-committing event. PostgreSQL documents that a locked counter table is the gapless alternative, though it is more expensive. Everquill’s projected append rate is low enough to choose correctness and simple replay ordering first. [PostgreSQL sequence documentation](https://www.postgresql.org/docs/current/sql-createsequence.html)

## 1. Canonical event store

This is production-shaped illustrative DDL. IDs must be generated by the command before persistence so retries and projection rebuilds produce stable identities.

```sql
CREATE SCHEMA IF NOT EXISTS canon;
CREATE SCHEMA IF NOT EXISTS read_model;
CREATE SCHEMA IF NOT EXISTS ops;

-- Transactional, commit-ordered global position allocator.
CREATE TABLE canon.event_global_clock (
    singleton       boolean PRIMARY KEY DEFAULT true CHECK (singleton),
    last_position   bigint NOT NULL CHECK (last_position >= 0)
);

INSERT INTO canon.event_global_clock (singleton, last_position)
VALUES (true, 0);

-- Payload schema documentation and Python upcaster registry.
CREATE TABLE canon.event_schema_registry (
    event_type              text NOT NULL
        CHECK (event_type ~ '^[a-z][a-z0-9_.-]+$'),
    schema_version          smallint NOT NULL CHECK (schema_version > 0),
    payload_json_schema     jsonb NOT NULL
        CHECK (jsonb_typeof(payload_json_schema) = 'object'),

    -- Old version N can name the Python upcaster that produces version N+1.
    upcasts_to_version      smallint,
    upcaster_id             text,

    introduced_at           timestamptz NOT NULL DEFAULT transaction_timestamp(),

    PRIMARY KEY (event_type, schema_version),

    CHECK (
        (upcasts_to_version IS NULL AND upcaster_id IS NULL)
        OR
        (
            upcasts_to_version > schema_version
            AND upcaster_id IS NOT NULL
        )
    )
);

-- Mutable coordination metadata, not canonical game state.
CREATE TABLE canon.event_stream (
    world_id            uuid NOT NULL,
    stream_id           uuid NOT NULL,
    stream_kind         text NOT NULL,
    current_version     bigint NOT NULL DEFAULT 0
        CHECK (current_version >= 0),
    created_at          timestamptz NOT NULL DEFAULT transaction_timestamp(),

    PRIMARY KEY (world_id, stream_id),
    UNIQUE (world_id, stream_id, stream_kind)
);

-- Command idempotency record. Written atomically with its events.
CREATE TABLE canon.event_command (
    world_id                uuid NOT NULL,
    command_id              uuid NOT NULL,
    request_fingerprint     bytea NOT NULL,
    actor_character_id      uuid,
    received_at             timestamptz NOT NULL DEFAULT transaction_timestamp(),
    first_global_position   bigint,
    last_global_position    bigint,
    result                  jsonb,

    PRIMARY KEY (world_id, command_id),

    CHECK (
        (first_global_position IS NULL)
        = (last_global_position IS NULL)
    ),
    CHECK (
        first_global_position IS NULL
        OR first_global_position <= last_global_position
    ),
    CHECK (
        result IS NULL OR jsonb_typeof(result) = 'object'
    )
);

CREATE TABLE canon.event_log (
    -- Allocated from event_global_clock inside the append transaction.
    global_position         bigint PRIMARY KEY CHECK (global_position > 0),

    event_id                uuid NOT NULL UNIQUE,
    world_id                uuid NOT NULL,

    -- Aggregate/stream ordering and optimistic concurrency.
    stream_id               uuid NOT NULL,
    stream_kind             text NOT NULL,
    stream_version          bigint NOT NULL CHECK (stream_version > 0),

    -- Idempotent command batch membership.
    command_id              uuid NOT NULL,
    command_event_index     smallint NOT NULL CHECK (command_event_index >= 0),

    -- Schema evolution.
    event_type              text NOT NULL,
    event_schema_version    smallint NOT NULL CHECK (event_schema_version > 0),
    envelope_version        smallint NOT NULL DEFAULT 1
        CHECK (envelope_version > 0),

    -- Typed routing/audit envelope.
    recorded_at             timestamptz NOT NULL DEFAULT transaction_timestamp(),
    world_time              bigint NOT NULL CHECK (world_time >= 0),
    actor_character_id      uuid,
    subject_entity_id       uuid,
    region_id               uuid,
    scene_id                uuid,
    causation_event_id      uuid,
    correlation_id          uuid NOT NULL,

    producer                text NOT NULL,
    producer_version        text NOT NULL,
    engine_ruleset_version  text,

    -- Set on random resolutions. Use a fresh per-resolution seed so revealing
    -- an old seed cannot predict future rolls.
    rng_algorithm           text,
    rng_seed                bytea,

    payload                 jsonb NOT NULL
        CHECK (jsonb_typeof(payload) = 'object'),
    metadata                jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(metadata) = 'object'),

    UNIQUE (world_id, stream_id, stream_version),
    UNIQUE (world_id, command_id, command_event_index),

    FOREIGN KEY (world_id, stream_id, stream_kind)
        REFERENCES canon.event_stream (world_id, stream_id, stream_kind),

    FOREIGN KEY (world_id, command_id)
        REFERENCES canon.event_command (world_id, command_id),

    FOREIGN KEY (event_type, event_schema_version)
        REFERENCES canon.event_schema_registry (event_type, schema_version),

    CHECK (
        rng_seed IS NULL
        OR octet_length(rng_seed) BETWEEN 16 AND 64
    )
);

-- Deed/roll/death queries and global projectors use typed columns.
CREATE INDEX event_log_type_position_idx
    ON canon.event_log (world_id, event_type, global_position);

CREATE INDEX event_log_subject_position_idx
    ON canon.event_log (world_id, subject_entity_id, global_position DESC)
    WHERE subject_entity_id IS NOT NULL;

CREATE INDEX event_log_region_world_time_idx
    ON canon.event_log
       (world_id, region_id, world_time, global_position)
    WHERE region_id IS NOT NULL;

CREATE INDEX event_log_scene_position_idx
    ON canon.event_log (world_id, scene_id, global_position DESC)
    WHERE scene_id IS NOT NULL;

CREATE INDEX event_log_correlation_idx
    ON canon.event_log (correlation_id);

-- Belt-and-suspenders immutability. The migration owner may disable this only
-- for a disaster-recovery procedure, never for event evolution.
CREATE FUNCTION canon.reject_event_mutation()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE EXCEPTION
        'canon.event_log is append-only; attempted operation: %', TG_OP;
END;
$$;

CREATE TRIGGER event_log_reject_mutation
BEFORE UPDATE OR DELETE OR TRUNCATE
ON canon.event_log
FOR EACH STATEMENT
EXECUTE FUNCTION canon.reject_event_mutation();
```

The migration role should own `canon.event_log`. Runtime roles should not own it, and should receive no `UPDATE`, `DELETE`, or `TRUNCATE` privilege. Ideally the runtime role gets only `EXECUTE` on an audited append function; otherwise grant the minimum `INSERT`/coordination rights required by the repository.

Do not add a general GIN index to `payload`. It would index nearly every key/value in every event and add substantial write amplification. PostgreSQL recommends targeted expression indexes when queries repeatedly inspect a known JSON path; `jsonb_path_ops` is usually smaller and faster for containment searches. [PostgreSQL JSONB indexing](https://www.postgresql.org/docs/current/datatype-json.html#JSON-INDEXING)

### Append transaction

For a batch containing `N` events:

1. Insert `event_command`. If `(world_id, command_id)` already exists, compare `request_fingerprint`; return the stored result or reject a mismatched reuse.
2. Create `event_stream` at version zero if this is its first command.
3. Reserve global positions:

```sql
UPDATE canon.event_global_clock
SET last_position = last_position + $1       -- $1 = N
WHERE singleton = true
RETURNING
    last_position - $1 + 1 AS first_position,
    last_position AS last_position;
```

4. Reserve stream versions using the caller’s expected version:

```sql
UPDATE canon.event_stream
SET current_version = current_version + $4   -- $4 = N
WHERE world_id = $1
  AND stream_id = $2
  AND current_version = $3                   -- expected version
RETURNING
    current_version - $4 + 1 AS first_version,
    current_version AS last_version;
```

If no stream row is updated, roll back and report an optimistic-concurrency conflict.

5. Insert every event with:

```text
global_position = first_position + batch_index
stream_version  = first_version + batch_index
```

6. Update `event_command` with its position range and durable response.
7. Apply latency-critical projections with the same deterministic projection handlers, if immediate read-after-write is required.
8. Commit before calling the narrator or any other network service.

The global-clock row remains locked until commit. That makes committed global positions contiguous and commit-ordered. Keep this transaction entirely local and short: intent parsing happens before it, narration happens after it, and no LLM call is ever made while the clock row is locked.

A sealed lethal resolution should append the resolution and `character.death_sealed` events atomically in the same batch. The death event must carry the complete factual death record, while the narrator consumes it only after commit.

A suitable roll payload is:

```json
{
  "action_id": "8d2562b7-92f0-40cb-9ee5-b23250873b31",
  "intent": {
    "action_type": "strike",
    "target_entity_id": "30f69175-1309-456d-a95d-df68e9535392",
    "approach": "spear"
  },
  "plausibility": "desperate",
  "inputs": {
    "character_stream_version": 41,
    "target_stream_version": 17,
    "known_modifiers": [
      {"code": "wounded_arm", "value": -1},
      {"code": "prepared_position", "value": 1}
    ]
  },
  "dice": {
    "faces": [2, 6],
    "modifier_total": 0,
    "total": 8
  },
  "outcome": "hit_with_complication",
  "deltas": [
    {"entity_id": "…", "field": "wounds", "operation": "append", "value": "pierced"}
  ]
}
```

The seed, RNG algorithm, engine/ruleset version, raw dice, known modifiers, inputs, and outcome make the resolution replayable without trusting narration.

## 2. Projection infrastructure

```sql
CREATE TABLE read_model.projection_checkpoint (
    projection_name         text NOT NULL,
    shard                   smallint NOT NULL DEFAULT 0,
    handler_version         text NOT NULL,
    last_global_position    bigint NOT NULL DEFAULT 0
        CHECK (last_global_position >= 0),
    status                  text NOT NULL DEFAULT 'live'
        CHECK (status IN ('building', 'live', 'failed')),
    last_error              text,
    updated_at              timestamptz NOT NULL DEFAULT transaction_timestamp(),

    PRIMARY KEY (projection_name, shard)
);
```

A projector transaction locks its checkpoint row, consumes events after `last_global_position`, updates projection rows, and advances the checkpoint atomically. Because global positions are commit-ordered, a scalar checkpoint is safe.

All projection IDs must come from event payloads. A projector must never invent a random claim, scene, relation, or job ID during replay.

### Private character sheet and true stats

`character_sheet_projection` is engine-only. It must not be granted to any narrator-facing or client-facing database role.

```sql
CREATE TABLE read_model.character_sheet_projection (
    world_id                uuid NOT NULL,
    character_id            uuid NOT NULL,
    character_stream_version bigint NOT NULL CHECK (character_stream_version >= 0),
    last_event_position     bigint NOT NULL CHECK (last_event_position >= 0),

    life_state              text NOT NULL
        CHECK (life_state IN ('alive', 'dying', 'dead', 'resurrected')),
    current_region_id       uuid,
    current_scene_id        uuid,
    current_world_time      bigint NOT NULL CHECK (current_world_time >= 0),

    conditions              jsonb NOT NULL DEFAULT '[]'::jsonb
        CHECK (jsonb_typeof(conditions) = 'array'),
    inventory               jsonb NOT NULL DEFAULT '[]'::jsonb
        CHECK (jsonb_typeof(inventory) = 'array'),
    equipment               jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(equipment) = 'object'),
    engine_flags            jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(engine_flags) = 'object'),

    PRIMARY KEY (world_id, character_id)
);

-- NUMERIC without a declared precision preserves Everquill's logically
-- uncapped integer progression better than int4/int8.
CREATE TABLE read_model.character_stat_projection (
    world_id            uuid NOT NULL,
    character_id        uuid NOT NULL,
    stat_key            text NOT NULL,
    true_value          numeric NOT NULL
        CHECK (true_value = trunc(true_value)),
    last_event_position bigint NOT NULL CHECK (last_event_position >= 0),

CREATE INDEX living_character_region_idx
    ON read_model.character_sheet_projection
       (world_id, current_region_id, character_id)
    WHERE life_state IN ('alive', 'resurrected');
```

## 3. Per-character claim store

Each row is one claim as known by one character through one provenance chain. Two sources making the same assertion should normally produce two claims linked by corroboration, rather than overwriting provenance.

`confidence` is evidence consistency on a 0–1000 internal scale, not truth probability. It need not be displayed as a bar.

```sql
CREATE TABLE read_model.character_claim (
    world_id                        uuid NOT NULL,
    claim_id                        uuid NOT NULL,
    knowledge_holder_character_id   uuid NOT NULL,

    -- Subject and assertion.
    subject_id                      uuid NOT NULL,
    subject_kind                    text NOT NULL,
    claim_key                       text NOT NULL,
    claim_text                      text NOT NULL,
    asserted_value                  jsonb,
    asserted_range                  numrange,
    value_unit                      text,

    -- Provenance.
    source_kind                     text NOT NULL,
    source_id                       uuid,
    source_label                    text NOT NULL,
    source_event_position           bigint NOT NULL
        CHECK (source_event_position > 0),

    observer_entity_id              uuid,
    observer_label                  text,
    acquisition_method              text NOT NULL,

    -- In-world timestamps, not server timestamps.
    observed_world_time             bigint NOT NULL
        CHECK (observed_world_time >= 0),
    learned_world_time              bigint NOT NULL
        CHECK (learned_world_time >= observed_world_time),

    -- Scope: local observations must not silently become universal claims.
    scope_kind                      text NOT NULL,
    scope_region_id                 uuid,
    scope_valid_from_world_time     bigint,
    scope_valid_to_world_time       bigint,
    scope_detail                    jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(scope_detail) = 'object'),

    -- Consistency of the supporting evidence, never truth probability.
    confidence                      smallint NOT NULL
        CHECK (confidence BETWEEN 0 AND 1000),
    confidence_basis                jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(confidence_basis) = 'object'),

    -- Inheritance.
    inheritance_status              text NOT NULL DEFAULT 'original'
        CHECK (
            inheritance_status IN (
                'original',
                'eligible',
                'bequeathed',
                'inherited',
                'rejected',
                'lost',
                'destroyed'
            )
        ),
    inherited_from_character_id     uuid,
    inherited_from_claim_id         uuid,
    inheritance_via_entity_id       uuid,
    inherited_at_world_time         bigint,

    -- Projection/context-selection fields.
    salience                        smallint NOT NULL DEFAULT 0,
    active                          boolean NOT NULL DEFAULT true,
    superseded_by_claim_id          uuid,
    created_event_position          bigint NOT NULL
        CHECK (created_event_position > 0),
    last_event_position             bigint NOT NULL
        CHECK (last_event_position >= created_event_position),

    PRIMARY KEY (world_id, claim_id),

    UNIQUE (
        world_id,
        knowledge_holder_character_id,
        claim_id
    ),

    FOREIGN KEY (world_id, inherited_from_claim_id)
        REFERENCES read_model.character_claim (world_id, claim_id),

    FOREIGN KEY (world_id, superseded_by_claim_id)
        REFERENCES read_model.character_claim (world_id, claim_id),

    CHECK (
        scope_valid_from_world_time IS NULL
        OR scope_valid_to_world_time IS NULL
        OR scope_valid_from_world_time <= scope_valid_to_world_time
    )
);

-- Directed: evidence_claim corroborates supported_claim.
CREATE TABLE read_model.claim_corroboration (
    world_id                        uuid NOT NULL,
    knowledge_holder_character_id   uuid NOT NULL,
    supported_claim_id              uuid NOT NULL,
    evidence_claim_id               uuid NOT NULL,

    strength                        smallint NOT NULL DEFAULT 1000
        CHECK (strength BETWEEN 0 AND 1000),
    rationale                       text,
    discovered_event_position       bigint NOT NULL
        CHECK (discovered_event_position > 0),

    PRIMARY KEY (
        world_id,
        knowledge_holder_character_id,
        supported_claim_id,
        evidence_claim_id
    ),

    FOREIGN KEY (
        world_id,
        knowledge_holder_character_id,
        supported_claim_id
    )
        REFERENCES read_model.character_claim (
            world_id,
            knowledge_holder_character_id,
            claim_id
        )
        ON DELETE CASCADE,

    FOREIGN KEY (
        world_id,
        knowledge_holder_character_id,
        evidence_claim_id
    )
        REFERENCES read_model.character_claim (
            world_id,
            knowledge_holder_character_id,
            claim_id
        )
        ON DELETE CASCADE,

    CHECK (supported_claim_id <> evidence_claim_id)
);

-- Symmetric contradiction edge. UUID ordering prevents mirrored duplicates.
CREATE TABLE read_model.claim_contradiction (
    world_id                        uuid NOT NULL,
    knowledge_holder_character_id   uuid NOT NULL,
    claim_low_id                    uuid NOT NULL,
    claim_high_id                   uuid NOT NULL,

    contradiction_kind              text NOT NULL,
    rationale                       text,
    discovered_event_position       bigint NOT NULL
        CHECK (discovered_event_position > 0),

    PRIMARY KEY (
        world_id,
        knowledge_holder_character_id,
        claim_low_id,
        claim_high_id
    ),

    FOREIGN KEY (
        world_id,
        knowledge_holder_character_id,
        claim_low_id
    )
        REFERENCES read_model.character_claim (
            world_id,
            knowledge_holder_character_id,
            claim_id
        )
        ON DELETE CASCADE,

    FOREIGN KEY (
        world_id,
        knowledge_holder_character_id,
        claim_high_id
    )
        REFERENCES read_model.character_claim (
            world_id,
            knowledge_holder_character_id,
            claim_id
        )
        ON DELETE CASCADE,

    CHECK (claim_low_id < claim_high_id)
);

-- Context assembler: top-K active claims for a known subject.
CREATE INDEX character_claim_context_idx
    ON read_model.character_claim (
        world_id,
        knowledge_holder_character_id,
        subject_id,
        salience DESC,
        observed_world_time DESC
    )
    INCLUDE (
        claim_key,
        confidence,
        source_kind,
        acquisition_method
    )
    WHERE active = true;

CREATE INDEX character_claim_region_idx
    ON read_model.character_claim (
        world_id,
        knowledge_holder_character_id,
        scope_region_id,
        observed_world_time DESC
    )
    WHERE active = true AND scope_region_id IS NOT NULL;

CREATE INDEX claim_contradiction_high_idx
    ON read_model.claim_contradiction (
        world_id,
        knowledge_holder_character_id,
        claim_high_id
    );

CREATE INDEX claim_corroboration_evidence_idx
    ON read_model.claim_corroboration (
        world_id,
        knowledge_holder_character_id,
        evidence_claim_id
    );
```

Claim rows and links remain projections. Their source events should be explicit operations such as:

- `claim.observed`
- `claim.inherited`
- `claim.corroborated`
- `claim.contradiction_discovered`
- `claim.superseded`
- `claim.lost`

A wrong claim is not edited into a correct one. Append new evidence and relationship events; the projection marks the old claim contradicted or superseded while preserving its provenance.

## 4. Perceived scene manifest

Store a manifest per viewer. This ensures the narrator and client consume the same fog-of-war-filtered entity set. Engine-only true scene state should live in a separately permissioned projection.

```sql
CREATE TABLE read_model.scene_manifest_projection (

    viewer_character_id         uuid NOT NULL,

    manifest_revision           bigint NOT NULL CHECK (manifest_revision >= 0),
    background_asset_id         uuid,

        CHECK (jsonb_typeof(perceived_environment) = 'object'),
    last_event_position         bigint NOT NULL CHECK (last_event_position >= 0),

);

CREATE TABLE read_model.scene_manifest_entity_projection (

    perceived_kind              text NOT NULL,

    perception_state            text NOT NULL
        CHECK (
            perception_state IN (
                'recognized',
                'seen_unknown',
                'silhouette',
                'hidden_detail'
            )
        ),

    position_x                  real NOT NULL,
    position_y                  real NOT NULL,
    depth_order                 integer NOT NULL DEFAULT 0,

    sprite_asset_id             uuid,
    known_sheet_subject_id      uuid NOT NULL,
    interaction_verbs           text[] NOT NULL DEFAULT '{}',

            world_id,
            scene_id,
            viewer_character_id

CREATE INDEX scene_entity_reverse_lookup_idx
    ON read_model.scene_manifest_entity_projection

```

The projection handler must verify that every manifested/tappable `entity_id` exists in canonical entity history. The narrator receives only this perceived projection, never the true scene projection.

## 5. Lazy rumor cache

The cache is regional, epoch-based, disposable, and derived on demand from deeds plus propagation rules. NPC-specific knowledge should be a cheap overlay, not a cached row for every NPC/deed pair.

```sql
CREATE TABLE read_model.rumor_cache_projection (
    world_id                    uuid NOT NULL,
    region_id                   uuid NOT NULL,
    epoch                       bigint NOT NULL CHECK (epoch >= 0),

    ruleset_version             text NOT NULL,
    epoch_world_time_start      bigint NOT NULL CHECK (epoch_world_time_start >= 0),
    epoch_world_time_end        bigint NOT NULL
        CHECK (epoch_world_time_end > epoch_world_time_start),

    built_from_global_position  bigint NOT NULL
        CHECK (built_from_global_position >= 0),
    built_at                    timestamptz NOT NULL DEFAULT transaction_timestamp(),

    rumors                      jsonb NOT NULL
        CHECK (jsonb_typeof(rumors) = 'array'),

    PRIMARY KEY (world_id, region_id, epoch)
);
```

On a cache miss or ruleset mismatch:

1. Query relevant deed events by region, world time, notoriety, and propagation horizon.
2. Deterministically distort/attenuate them.
3. Upsert the region-epoch cache.
4. Apply observer-specific filters without persistent eager fan-out.

## 6. Timer and due-job projection

This is an at-least-once work queue. The scheduling, completion, cancellation, and failure facts are events; leases and worker ownership are operational projection state.

```sql
CREATE TABLE ops.timer_job (
    world_id                    uuid NOT NULL,
    job_id                      uuid NOT NULL,
    job_type                    text NOT NULL,
    character_id                uuid,

    scheduled_event_position    bigint NOT NULL
        CHECK (scheduled_event_position > 0),
    due_world_time              bigint NOT NULL CHECK (due_world_time >= 0),
    due_at                      timestamptz NOT NULL,

    status                      text NOT NULL DEFAULT 'ready'
        CHECK (
            status IN (
                'ready',
                'running',
                'blocked',
                'done',
                'cancelled',
                'dead'
            )
        ),

    attempts                    integer NOT NULL DEFAULT 0 CHECK (attempts >= 0),
    max_attempts                integer NOT NULL DEFAULT 8 CHECK (max_attempts > 0),

    worker_id                   text,
    leased_at                   timestamptz,
    lease_until                 timestamptz,

    dedupe_key                  text,
    payload                     jsonb NOT NULL DEFAULT '{}'::jsonb
        CHECK (jsonb_typeof(payload) = 'object'),

    completed_event_position    bigint,
    last_error                  text,
    created_at                  timestamptz NOT NULL DEFAULT transaction_timestamp(),
    updated_at                  timestamptz NOT NULL DEFAULT transaction_timestamp(),

    PRIMARY KEY (world_id, job_id),

    CHECK (
        status <> 'running'
        OR (
            worker_id IS NOT NULL
            AND leased_at IS NOT NULL
            AND lease_until IS NOT NULL
        )
    )
);

CREATE UNIQUE INDEX timer_job_dedupe_idx
    ON ops.timer_job (world_id, dedupe_key)
    WHERE dedupe_key IS NOT NULL;

CREATE INDEX timer_job_due_idx
    ON ops.timer_job (due_at, job_id)
    INCLUDE (world_id, job_type)
    WHERE status = 'ready';

CREATE INDEX timer_job_expired_lease_idx
    ON ops.timer_job (lease_until, job_id)
    WHERE status = 'running';
```

Worker claim query:

```sql
WITH picked AS MATERIALIZED (
    SELECT world_id, job_id
    FROM ops.timer_job
    WHERE status = 'ready'
      AND due_at <= clock_timestamp()
    ORDER BY due_at, job_id
    FOR UPDATE SKIP LOCKED
    LIMIT $1
)
UPDATE ops.timer_job AS job
SET
    status = 'running',
    worker_id = $2,
    leased_at = clock_timestamp(),
    lease_until = clock_timestamp() + ($3 * interval '1 second'),
    attempts = attempts + 1,
    updated_at = clock_timestamp()
FROM picked
WHERE job.world_id = picked.world_id
  AND job.job_id = picked.job_id
RETURNING job.*;
```

`SKIP LOCKED` deliberately gives an inconsistent view, which PostgreSQL identifies as suitable for multiple consumers of a queue-like table. It should not be used for ordinary gameplay reads. [PostgreSQL locking clause documentation](https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE)

Worker rules:

- Expired leases return to `ready` unless attempts reached `max_attempts`.
- Completion appends a canonical event using `job_id` as the idempotent command ID, then marks the projection row `done` in the same transaction.
- A crash can rerun a job, so handlers and external batch submissions need deterministic idempotency keys.
- Never treat `status = 'done'` alone as proof that gameplay completed; the canonical completion event is proof.
- Rebuilding the timer projection replays scheduled/completed/cancelled events and reconstructs pending jobs.

## 7. Projection and upcasting rules

Use two independent version dimensions:

- `envelope_version`: structure and semantics of typed event-envelope columns.
- `event_schema_version`: payload version scoped to one `event_type`.

Rules:

1. Never rewrite historical event payloads.
2. Deserialize, validate the stored version, then run pure Python upcasters sequentially until the current in-memory version.
3. Upcasters may rename/default/reshape data; they may not query current game state or call an LLM.
4. Store the upcaster chain in code; the registry records which chain is expected.
5. Keep golden fixtures for every historical event version.
6. When projection logic changes, increment `handler_version` and rebuild into empty or shadow projection tables.
7. Projection upserts should be idempotent and normally guarded by `last_event_position`.
8. Do not place foreign keys from projection `*_event_position` columns to `event_log`. Positions are audit pointers; avoiding those FKs makes shadow rebuilds and future partition migration substantially easier.

## 8. Partitioning

### Alpha verdict: do not partition

At tens of players and low hundreds of events per heavy player per day, a regular PostgreSQL table is simpler and comfortably sufficient. Partitioning adds migration, uniqueness, index-management, and query-planning complexity before it provides value.

PostgreSQL’s own rule of thumb is that partitioning usually becomes useful when the table exceeds database-server physical memory. It also warns that unique/primary constraints on partitioned tables must include every partition-key column. [PostgreSQL partitioning guidance](https://www.postgresql.org/docs/current/ddl-partitioning.html)

Prepare now by:

- Using `bigint` positions and versions.
- Keeping access behind an append repository/function.
- Querying through typed columns.
- Avoiding projection-to-event foreign keys.
- Recording table/index sizes and `EXPLAIN (ANALYZE, BUFFERS)` results.
- Load-testing realistic event sizes and stream distributions.

Revisit partitioning when one or more are observed:

- Roughly tens to hundreds of millions of events.
- Event-table or hot-index size exceeds available memory.
- Vacuum, backup, restore, or index-maintenance windows become problematic.
- Measured global replay or per-stream audit latency degrades.
- The 10,000-player case approaches roughly 0.4–1.1 billion events/year.

### Likely future choices

**Hash by `stream_id`**, perhaps 32 partitions:

- Keeps a character/world aggregate in one partition.
- Allows per-stream uniqueness because the partition key is included.
- Global projection scans become a merge across partition-local `global_position` indexes.
- Global-position uniqueness remains enforced by the transactional allocator and append function rather than a parent unique constraint.

**Range by `global_position`**, perhaps 25–100 million positions per partition:

- Excellent for global replay, backup segmentation, and sequential access.
- Per-stream uniqueness cannot be declared globally unless `global_position` is also included, so correctness must rely on `event_stream` and the append function.
- A single stream spans historical partitions.

Benchmark both against actual workloads before choosing. Do not create one partition per player, character, region, or month-by-default; thousands of partitions increase planning and memory overhead.

## 9. What not to build for alpha

- No Kafka, Debezium, CDC pipeline, or event-bus microservices.
- No EventStoreDB/KurrentDB beside PostgreSQL.
- No graph database for claims; two indexed edge tables are sufficient.
- No vector database for narrator context selection.
- No eager rumor fan-out per deed × region × NPC.
- No generic workflow engine for timers.
- No read replicas, sharding, or multi-region writes.
- No broad GIN indexes on event or claim JSONB.
- No aggregate snapshot subsystem yet; current projections already serve as rebuildable snapshots.
- No database triggers implementing game rules or projection logic.
- No `LISTEN/NOTIFY` as durable delivery. It may later be used only as a wake-up hint; checkpoints remain authoritative.
- No cryptographic hash chain, Merkle tree, or blockchain. Append-only privileges, sealed transactions, audited payloads, backups, and replay verification are enough unless adversarial database administrators enter the threat model.
- No database RLS unless clients later obtain direct database access; the current API-only architecture should never expose database credentials.
- No generic “one JSON document per character” source-of-truth table.

## 10. Python framework verdict

### Verdict: build a thin event repository on plain psycopg3

Use:

- `psycopg`
- `psycopg_pool`
- SQL migrations
- Small Python event/upcaster/projector modules
- Parameterized SQL and explicit transaction boundaries

Psycopg supports synchronous and asynchronous operation, pooling, COPY, prepared statements, and pipeline mode. Its documentation recommends explicit transaction management and warns against leaving long-running connections idle in a transaction. [Psycopg transaction management](https://www.psycopg.org/psycopg3/docs/basic/transactions.html), [Psycopg pooling](https://www.psycopg.org/psycopg3/docs/advanced/pool.html)

The Python `eventsourcing` library is credible: its current stable documentation supports PostgreSQL through Psycopg 3, aggregate versions, an application notification sequence, subscriptions, projections, and tracking records. However, its core stored-event abstraction is essentially `originator_id`, `originator_version`, class `topic`, and serialized `state`. Everquill needs a first-class typed envelope with world time, actor, subject, region, scene, causation, engine/ruleset, RNG audit, command idempotency, and explicit JSONB payload versions. Customizing the library’s recorder and mapper enough to preserve those requirements would remove much of its benefit. [Python `eventsourcing` persistence](https://eventsourcing.readthedocs.io/en/stable/topics/persistence.html), [`eventsourcing` projections](https://eventsourcing.readthedocs.io/en/stable/topics/projection.html)

Therefore:

| Decision | Verdict |
|---|---|
| Psycopg3 + pool | Buy/use |
| Thin append repository | Build |
| Python upcasters | Build |
| Deterministic projection handlers | Build |
| `eventsourcing` framework | Skip for alpha; borrow its notification/tracking concepts |
| Dedicated event-store database | Skip |
| ORM on the append path | Skip; raw parameterized SQL is clearer |
| ORM for admin/reporting projections | Optional later |

Reconsider a framework only if Everquill develops multiple independently deployed event-consuming services and maintaining subscriptions, tracking, snapshots, and process managers becomes a larger burden than preserving the custom envelope.

## 11. Minimum acceptance tests

1. Two commands append to the same expected stream version concurrently: exactly one succeeds.
2. Two retries use the same command ID and fingerprint: both return the same committed positions/result.
3. Reusing a command ID with a different fingerprint fails.
4. Two streams append concurrently: projectors observe events strictly in committed global-position order.
5. Runtime database roles cannot update, delete, or truncate events.
6. Replaying from position zero recreates character, known-sheet, claim, scene, rumor, and timer projections.
7. Replaying the same events twice changes nothing.
8. Every historical payload version upcasts to the current in-memory event.
9. A stored roll reproduces its raw dice and outcome under its recorded engine/RNG versions.
10. A crash before and after timer completion produces at most one canonical completion event.
11. A sealed death is committed before any narration and remains present after full projection deletion/rebuild.
12. Narrator/client database paths cannot select private true-sheet or true-scene projections.
